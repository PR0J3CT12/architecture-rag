# Проектная работа 7: RAG-бот для QuantumForge Software

## Задание 1. Исследование моделей и инфраструктуры

### 1.1 Сравнение LLM-моделей

| Критерий | Локальные (Mistral-7B, LLaMA-3) | OpenAI GPT-4o | YandexGPT Pro | Gemini 1.5 Flash |
|---|---|---|---|---|
| Качество ответов | Заметно хуже облачных — маленькие модели плохо следуют инструкциям и теряют контекст | Лучшее из рассмотренных | Хуже GPT-4o, зато лучше на русском | Чуть хуже GPT-4o, для RAG-задачи достаточно |
| Скорость работы | Медленно без GPU, на CPU неприемлемо для интерактивного бота | Быстро | Быстро | Быстрее всех из облачных |
| Стоимость | Платишь за GPU-сервер, не за токены. При малых объёмах выходит дороже | Самый дорогой из облачных | Средняя | Самый дешёвый из облачных, есть бесплатный тир |
| Простота развёртывания | Сложно: GPU-сервер, Ollama/vLLM, MLOps-навыки | Просто: API-ключ и готово | Просто: API-ключ и готово | Просто: API-ключ и готово |

**Вывод:** Локальные модели отпадают — сложно и медленно без GPU. GPT-4o избыточен по цене для этой задачи. YandexGPT полезен при русскоязычной базе, но нужно копаться в Yandex Cloud :). Выбираю **Gemini 1.5 Flash** — дешевле всех, быстрее всех, проще всего подключить.

### 1.2 Сравнение моделей эмбеддингов

| Критерий | Sentence-Transformers (all-MiniLM-L6-v2) | OpenAI text-embedding-ada-002 | Google text-embedding-004 |
|---|---|---|---|
| Скорость создания индекса | Быстрее всех — работает локально, нет сетевых задержек и rate limit | Медленнее локальной из-за API-вызовов | Медленнее локальной, но лимиты щедрее чем у OpenAI |
| Качество поиска | Хуже облачных — маленькая модель, плохо справляется со специализированными терминами | Хорошее, входит в топ MTEB-бенчмарка | Сопоставимо с OpenAI, тоже в топе MTEB |
| Стоимость | Бесплатно — только ресурсы сервера | Платно за каждый токен | Бесплатно в рамках Gemini API |

**Вывод:** Выбираю **Google text-embedding-004** — бесплатно, качество не хуже OpenAI, и уже в одной экосистеме с Gemini.

### 1.3 Сравнение векторных баз данных

| Критерий | FAISS | ChromaDB |
|---|---|---|
| Скорость поиска и индексации | Быстрее — работает в памяти, создан Meta именно для высоконагруженного поиска | Медленнее — использует SQLite под капотом, есть накладные расходы |
| Сложность внедрения и поддержки | Просто поставить, но персистентность надо писать руками — сохранить индекс в файл и загрузить при старте | Немного проще — сохраняется автоматически, есть фильтрация по метаданным из коробки |
| Удобство в работе | Нет UI, нет встроенной фильтрации. Зато отлично интегрируется с LangChain | Удобнее для разработки: богаче API, можно фильтровать по метаданным, есть визуализация через ChromaDB UI |
| Стоимость владения | Бесплатно, open source. Дополнительной инфраструктуры не нужно — работает как библиотека | Бесплатно, open source. Для prod-использования может понадобиться отдельный сервер, что добавляет расходы |

**Вывод:** Для 18 000+ документов QuantumForge выбираю **FAISS** — быстрее, не требует дополнительной инфраструктуры, достаточно для задачи.

### 1.4 Варианты конфигурации для QuantumForge Software

| # | LLM | Эмбеддинги | Векторная БД | Сервер | Когда подходит |
|---|---|---|---|---|---|
| A  | Gemini 1.5 Flash | Google text-embedding-004 | FAISS | 2 vCPU, 4 GB RAM, без GPU | MVP, быстрый старт, документация не секретная |
| B | Gemini 1.5 Flash | all-MiniLM-L6-v2 (локально) | FAISS | 4 vCPU, 8 GB RAM | Нужно чтобы документы не уходили наружу при индексации |
| C | Mistral-7B (Ollama) | all-MiniLM-L6-v2 | FAISS | 8 vCPU, 32 GB RAM, GPU 16 GB | Полная приватность, SOC 2, данные клиентов не покидают периметр |
| D | GPT-4o Enterprise | OpenAI text-embedding-3-large | Qdrant | EKS (уже есть в компании) | После успешного пилота, масштаб на всю компанию |

**Выбран вариант A** — QuantumForge уже работает в облаке (AWS), данные инженерной документации не являются гостайной, а быстрый старт важнее абсолютной приватности на этапе пилота. Если SOC 2 потребует ограничений — перейти на вариант C несложно, архитектура позволяет.
